GitHub Data Sync

Pulls shared master data from a private GitHub repository so every device starts from the same catalog and history, with full commit history for recovery. Push to GitHub commits this device's current data back to the repo (one atomic commit; only changed files). Requires a fine-grained personal access token scoped to only the data repo — the token is stored only on this device. When configured, TIM syncs automatically on startup.

Master JSON Schema (v1.27)

All data lives in Calix_Odoo_Converter_source_data.json. Top-level keys:

KeyContentsNotes

history.recordsReceiving history (Calix/RMA imports)Existing structure — unchanged
inventory_sessionsClosed inventory session metadataAdded v1.27; one record per finalized session
inventory_eventsAll finalized inventory events (flat array)Added v1.27; each event carries its sessionId

Tracking Types

TypeMeaningInventory behavior
serialEach physical unit has a unique serial numberOne event per scan; duplicate detection active
reelCable/fiber reel tracked by footage via sequence numbersOpens reel modal; records footage per span
noneBulk item — count only, no individual trackingSimple quantity entry; location-level count

Data Retention Policy

On every master JSON export (and on Finalize Session), inventory_events older than 10 years are automatically purged. history.records (receiving history) and inventory_sessions metadata are never auto-purged — they are small and serve as the permanent audit trail.

Session Finalize Workflow

  1. Load master JSON in the Receiving tab (Step 1).
  2. Run the inventory session in the Inventory tab.
  3. Click Finalize & Merge to Master JSON when the count is complete.
  4. The session is marked closed; all events are merged into inventory_events with their sessionId.
  5. An updated master JSON is downloaded automatically — replace the previous master file.

Item History View

Click the History button next to any product in the catalog above to see: all receiving records (from history.records) and all inventory events across every finalized session (from inventory_events), grouped by session with quantity/footage totals.

Assumptions to Validate After Real Use

  • Is the average locations-per-item actually ≤ 8? Check the item history view for multi-location items.
  • Is the master JSON file size growing faster than expected? If it exceeds ~80 MB, consider lowering the purge window to 5 years.
  • Are there product types that don't fit serial / reel / none cleanly? Flag them — we may need a 4th tracking type.
  • Is the "Finalize" workflow creating too much friction? Consider an auto-finalize on session clear as an alternative.
